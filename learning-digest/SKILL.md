# Learning Digest

把近期学习内容当作待筛选的原料，而不是默认全部归档。目标是帮助用户留下能改变未来理解或行动的知识，避免长期笔记退化为教材抄写、语法摘录和资料收藏。

## 选择证据

只读取当前环境中与本次判断有关、且实际可访问的内容。可按需参考：

- 最近修改的代码与 Git diff
- 调试过程、报错、失败尝试和修复结果
- 用户提供的学习记录、对话上下文或实验结果
- 已有笔记的主题与组织方式
- 当前项目的目标、约束和实现

从最相关、成本最低的证据开始；已有信息足够时停止。不要为了显得全面而强制读取所有来源，也不要假装看过不可访问的历史、笔记或调试记录。缺少关键上下文时，明确说明判断依据有限；只有当缺失信息会显著改变结论时才向用户追问。

## 判断长期价值

综合判断一条内容是否会在未来帮助用户理解、诊断、设计或表达。重点考察：

- **获得成本**：是否来自真实踩坑、实验、调试或艰难推理，而非随手可查的事实。
- **复发概率**：用户是否已经反复犯错，或未来很可能再次遇到。
- **机制深度**：是否揭示了因果链、边界条件、失败模式或容易误解的内部机制。
- **迁移范围**：是否能应用到其他项目、语言、框架或问题类型。
- **认知变化**：是否形成或修正了重要 mental model，而不只是增加一个知识点。
- **混淆风险**：是否与相邻概念相似，容易在实践中选错或解释错。
- **证据强度**：结论是否有代码、实验、日志或真实结果支持；区分观察、解释与尚未验证的猜测。

据此分为三类：

### 不用记

通常包括基础常识、容易查到且无需上下文的事实、用户已经熟练的内容、单纯语法细节、没有复用价值的偶然信息，以及只收藏了链接却没有形成理解的材料。

不要仅因内容“新”或“技术性强”就建议记录。如果一个细节虽容易查询，但它曾导致真实故障或暴露关键误解，仍可建议记录其背后的机制和诊断线索，而不是抄录该细节本身。

### 值得记

通常包括亲自踩过的坑、反复出现的错误、难理解的机制、重要 mental model、可迁移的解题或调试思路、由实验得到的认识，以及容易混淆且会影响决策的概念。

建议记录“以后需要重新想起来的最小完整单元”：问题背景、原先误解、关键机制、证据或最小例子、适用边界，以及下次可执行的判断或检查。不要把完整教程或探索过程原样搬进长期笔记。

### 值得输出

“值得输出”是“值得记”中具有公共表达价值的子集。通常需要具备完整问题背景、真实踩坑过程、可复现代码或实验、非显然的理解，以及对其他人也有帮助的迁移价值。

内容适合长期笔记但证据不足、故事不完整或过度依赖私人上下文时，不要勉强建议写博客。指出若要发展为博客还缺什么，例如最小复现、对照实验、机制验证、边界案例或更清晰的叙事主线。

## 推荐归档位置

优先匹配已有笔记，而不是创建新的零散文件。根据内容的稳定用途建议归入某一类，例如：

- 概念或机制笔记：解释长期稳定的工作原理与 mental model
- 项目笔记：记录只在当前项目约束下成立的设计决定和上下文
- 调试 / 故障复盘：记录症状、错误假设、定位路径、根因和预防办法
- 实验记录：保留假设、环境、步骤、结果和结论边界
- 模式 / 清单：沉淀可重复使用的诊断步骤、设计原则或决策规则
- 主题索引或 MOC：只在内容主要用于连接已有多篇笔记时使用

如果能看到已有笔记，基于其真实名称、主题和粒度推荐具体归属；看不到时只建议笔记类型，不要虚构文件名或目录。只有当内容形成独立、可持续扩展的主题且无法自然并入现有笔记时，才建议新建笔记。

## 首次输出

默认先给出筛选结果，不修改任何笔记。输出应让用户能直接决定是否记录，至少覆盖：

1. **不建议记录**：列出内容及简短理由；相似项可合并。
2. **建议记录**：说明应保留的核心认识、为什么有长期价值，以及支持判断的实际证据。
3. **建议归属**：优先指出已有哪篇或哪类笔记适合更新；无法确定时明确说明。
4. **博客潜力**：标为“不值得”“暂不值得”或“值得”，并说明理由；若尚缺材料，列出最关键的补充项。

不要为了填满分类而强行制造条目。若没有值得记录或值得写博客的内容，直接说明。把不确定判断标出来，不把推测包装成结论。

## 用户要求写入时

只有用户明确要求写入、整理或更新笔记后，才执行修改。写入前确认目标笔记可识别；若多个位置都合理且选择会显著改变组织方式，再请用户决定。

编辑时：

- 优先更新已有笔记，保持其原有结构、语气、链接方式和粒度。
- 提炼结论与证据，不复制整段聊天、日志、教程或代码。
- 保留必要的真实上下文与最小可复现示例，删除无助于未来理解的过程噪声。
- 明确适用条件、已验证事实和仍待验证的推断。
- 新建笔记前再次确认无法自然并入已有内容；不要顺手创建额外索引或配套文件。

如果用户只要求评估、复盘或推荐，不要把它解释为写入授权。
